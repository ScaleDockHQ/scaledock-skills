## Part Two: Experience API Data

Source: https://raw.githubusercontent.com/adlnet/xAPI-Spec/ca782a1129bc6ae848640ff4e8e262334bdd0ba5/xAPI-Data.md

- **§ 2.2 Formatting Requirements.** A Statement MUST use each property no more than one time.
- **§ 2.2 Formatting Requirements.** A Statement MUST use "actor", "verb", and "object".
- **§ 2.2 Learning Record Provider Requirements.** Values requiring IRIs MUST be sent with valid IRIs.
- **§ 2.2 Learning Record Provider Requirements.** Keys of language maps MUST be sent with valid [RFC 5646](http://tools.ietf.org/html/rfc5646) language tags, for similar reasons.
- **§ 2.2 LRS Requirements.** The LRS MUST process and store numbers with at least the precision of IEEE 754 32-bit floating point numbers.
- **§ 2.3.2 Voiding.** When issuing a Statement that voids another, the Object of that voiding Statement MUST have the "objectType" property set to `StatementRef`.
- **§ 2.3.2 Voiding.** An LRS MUST consider a Statement it contains voided if and only if the Statement is not itself a voiding Statement and the LRS also contains a voiding Statement referring to the first Statement.
- **§ 2.4.1 ID.** Statement ids MUST be generated by the LRS if a Statement is received without an id.
- **§ 2.4.2.2 Requirements for Identified Groups.** An Identified Group MUST include exactly one (1) Inverse Functional Identifier.
- **§ 2.4.3 Verb Id Requirements.** A single Verb IRI MUST NOT be used to refer to multiple meanings.
- **§ 2.4.3 Verb Display Learning Record Consumer Requirements.** A Learning Record Consumer MUST NOT use the "display" property to infer any meaning from the Statement.
- **§ 2.4.4.1 Activity id Requirements.** An Activity id MUST always reference the same Activity.
- **§ 2.4.4.3 SubStatements.** A SubStatement MUST NOT contain a SubStatement of its own, i.e., cannot be nested.
- **§ 2.4.7 Timestamp.** A Learning Record Provider MUST NOT use a future time for a "timestamp" property in a Statement.
- **§ 2.4.8 Stored.** The "stored" property MUST be set by the LRS; An LRS SHOULD validate and then MUST overwrite any value currently in the "stored" property of a Statement it receives.

## Part Three: Data Processing, Validation, and Security

Source: https://raw.githubusercontent.com/adlnet/xAPI-Spec/ca782a1129bc6ae848640ff4e8e262334bdd0ba5/xAPI-Communication.md

- **§ 1.4 Encoding.** All strings MUST be encoded and interpreted as UTF-8.
- **§ 2.1.1 PUT Statements.** An LRS MUST NOT make any modifications to its state based on receiving a Statement with a statementId that it already has a Statement for.
- **§ 2.1.3 GET Statements.** The LRS MUST not return any Statement which has been voided, unless that Statement has been requested by voidedStatementId.
- **§ 3.1 Concurrency.** An LRS responding to a GET request MUST add an ETag HTTP header to the response.
- **§ 3.2 Error Codes.** The LRS MUST reject a batch of statements if any Statement within that batch is rejected.
- **§ 3.3 Versioning.** The LRS MUST include the "X-Experience-API-Version" header in every response.
- **§ 3.3 Versioning.** The LRS MUST reject requests with a version header of `1.1.0` or greater.
- **§ 3.3 Versioning.** The Client MUST include the "X-Experience-API-Version" header in every request.
- **§ 4.0 Authentication.** The LRS MUST support authentication using at least one of the authentication methods defined in this specification.
