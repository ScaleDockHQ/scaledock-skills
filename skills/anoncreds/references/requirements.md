## AnonCreds 1.0

Source: https://anoncreds.github.io/anoncreds-spec/

The AnonCreds (Anonymous Credentials) specification is based on the open source verifiable credential

- **§ Requirements, Notation and Conventions.** The key words “MUST”, “MUST NOT”, “REQUIRED”, “SHALL”, “SHALL NOT”, “SHOULD”, “SHOULD NOT”, “RECOMMENDED”, “NOT RECOMMENDED”, “MAY”, and “OPTIONAL” in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.
- **§ AnonCreds Setup Data Flow.** The DID of the publisher of an AnonCreds object MUST be identifiable from the published object and enforcement of the relationship between the DID and the object must be enforced.
- **§ Schema Publisher: Publish Schema Object.** MUST adhere to Issuer Identifiers rules.
- **§ Generating a Credential Definition Without Revocation Support.** The Issuer SHOULD provide a published key correctness proof based on the approach described in Jan Camenisch and Markus Michels.
- **§ Revocation Registry Definition Object Generation.** MUST adhere to Issuer Identifiers rules and MUST be the same issuerId as the Credential Definition on which the Revocation Registry is based.
- **§ Create Presentation Request.** The verifier SHOULD validate that the presentation satisfies the business requirements for which the presentation was provided.
- **§ Create Presentation Request.** version is a string set by the verifier , the version of the presentation request nonce is a string, a decimal, 80-bit number generated by the verifier that SHOULD be unique per presentation request .
- **§ Create Presentation Request.** “1.0” to use unqualified identifiers for restrictions “2.0” to use fully qualified identifiers for restrictions attr_info has the following format: { "name" : <string> , "names" : < [ string , string ] > , "restrictions" : <restrictions> , "non_revoked" : <non_revoc_interval> , } All of the items are optional, but one of name or names MUST be included, and not both.
