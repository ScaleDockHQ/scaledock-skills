## Password Storage Cheat Sheet

Source: https://raw.githubusercontent.com/OWASP/CheatSheetSeries/29994dd8a2e6f50fa3d5607b046b54d7c6945afd/cheatsheets/Password_Storage_Cheat_Sheet.md

- **Password Storage: Introduction.** Passwords should never be stored in plain text.
- **Password Storage: Introduction.** A unique salt must be added to each password to prevent attackers from using precomputed lookup tables like rainbow tables.
- **Password Storage: Argon2id.** Out of the three Argon2 versions, use the Argon2id variant since it provides a balanced approach to resisting both side-channel and GPU-based attacks.

## Session Management Cheat Sheet

Source: https://raw.githubusercontent.com/OWASP/CheatSheetSeries/29994dd8a2e6f50fa3d5607b046b54d7c6945afd/cheatsheets/Session_Management_Cheat_Sheet.md

- **Session Management: Session ID Entropy.** Session identifiers must have at least `64 bits` of entropy to prevent brute-force session guessing attacks.
- **Session Management: Session ID Content (or Value).** The session ID must simply be an identifier on the client side, and its value must never include sensitive information or Personally Identifiable Information (PII).
- **Session Management: SameSite Attribute.** Session cookies must explicitly set `SameSite=Strict` (preferred) or `SameSite=Lax`.
- **Session Management: Renew the Session ID After Any Privilege Level Change.** The session ID must be renewed or regenerated by the web application after any privilege level change within the associated user session.

- **Input Validation: Common Pitfalls.** Validate on the server even when the browser checks the same fields.

## Secrets Management Cheat Sheet

Source: https://raw.githubusercontent.com/OWASP/CheatSheetSeries/29994dd8a2e6f50fa3d5607b046b54d7c6945afd/cheatsheets/Secrets_Management_Cheat_Sheet.md

- **Secrets Management: 2.7.1 Creation.** Secrets must have the minimum privileges assigned to them to enable their required use/role.
- **Secrets Management: 2.7.3 Revocation.** When secrets are no longer required or potentially compromised, you must securely revoke them to restrict access.
- **Secrets Management: 9.2 Remediation.** Secrets revoked/rotated must be removed from the exposed system immediately, including secrets discovered in code or logs.
